# 設計

## 目的・優先順位

festはYouTube Musicをターミナルで検索・選曲・再生するプレイヤーです。
操作の使いやすさ、認証情報の保護、各OSでの配布・保守を優先します。

## 対象・完了条件

- macOS arm64/amd64・Linux amd64・Windows amd64に対応します。追加の実行環境やWSLは要求しません。
- 検索・選曲・キュー・一時停止・音量・シークに対応し、終了時は再生も停止します。
- ゲストと保存アカウントを選択でき、認証後はライブラリ・プレイリストを読み取れます。
- 設定・アカウントの変更と保存データの削除をコマンドから行えます。
- テスト・ビルド・実サービス接続・ログイン・実機の音声出力を別々に確認します。

## 構成・制約

- CLI・TUI・サービス接続・設定管理はGoで実装します。TUIと通信を分離し、検索・曲切替・終了で不要な処理を中止します。
- 音声URLの取得はadapterに分離し、指定されたYouTube Musicの曲IDを使用します。
- AAC/Opusは同梱するLGPL構成のFFmpegでデコードし、Goの音声ライブラリで出力します。GPL・nonfreeの部品は含めません。
- 通信はGo側でHTTPSと接続先を検証し、音声データをメモリpipeで渡します。認証情報・音声URLを引数・ログ・平文一時ファイルへ出しません。
- FFmpegの起動・停止・回収はアプリが管理します。同梱依存のhash・ライセンス・対応ソースを揃えます。
- シークは先頭から指定位置まで読み進めるため、長い曲では待ち時間が増えます。
- Linuxはglibc 2.28以降とPulseAudio/PipeWireの互換サービスを対象とします。署名・公証は未設定です。

## 保存・復旧

- 保存先は`MUSIC_CLI_HOME`またはOS標準の専用領域です。所有markerとconfig/vault v1を使用します。
- 認証情報はscrypt/AES-256-GCMで暗号化します。Keychain・OS資格情報を使わず、復号鍵・パスフレーズは保存しません。
- 未知の形式・symlink・不正なmarker・競合更新は拒否します。保存は原子的に行い、purgeは既知の所有ファイルだけを削除します。
- 認証情報は非表示で入力し、Googleパスワードの取得やブラウザDBの自動読取りは行いません。
- 復旧時は全festを終了し、アプリ一式を戻します。保存形式が異なる場合は、対応する暗号化vaultも復元します。

## 保守・拡張境界

- 保守は月1回を基本とし、依存更新も同じ製品テストと配布検査で確認します。アプリの自動更新は行いません。
- Spotify/Apple Music・プレイリスト編集・ダウンロード・daemon・OAuthは対象外です。
- サービス追加時はproviderをサービスIDで分離し、検索結果とキューを同じサービス内に限定します。
- 認証拡張はservice・credential kind付きのvault v2で扱います。v1をYouTube Musicのbrowser headersとして検証し、バックアップ後の明示操作で原子的に変換します。未知の形式の上書きは拒否します。
- OAuthはclient登録・scope・利用条件を確定して導入します。daemonはOSユーザー限定のlocal IPCを使い、終了・purge前に停止します。公開portや認証平文のIPCファイルは作りません。
- 高速シークはseek可能な入力adapter、ALSA対応は音声backendとビルド条件の追加で扱います。処理の中止と認証情報の保護を維持します。
